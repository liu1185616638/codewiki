# 安全模型与边界

## 基本信任边界

代码仓库、README、注释、配置、Git 元信息、文档、远程 URL 都是不可信输入。模型提示词中包含的仓库文字也不具有指令权限。项目默认只读取源码并建立索引，不运行编译构建、测试脚本、Git hooks、仓库 MCP/Agent 指令或 shell 命令。

## 当前 Phase 0 安全能力

- `ignore::WalkBuilder` 尊重 Git ignore 规则和 `.codewikiignore`；不跟随符号链接。
- 排除 `.env`、`.env.*`、常见私钥/凭据文件和私钥后缀；仍可能漏掉自定义命名的敏感信息。
- 跳过二进制、无效 UTF-8、超 1 MiB 文件；目前不支持编码探测/GBK。
- `scan` 不请求网络，不执行源仓库脚本，不调用 AI。
- `generate` 默认拒绝覆盖同名现有文件；`--overwrite` 仅适合生成专用输出目录。

**局限**：Phase 0 的过滤不等于完整秘密检测，也不等于安全沙箱。扫描本地工作树可能包括未经 Git 提交的文件。请勿将扫描报告直接公开或发送到模型服务。

## 后续必须执行的安全设计

1. **Git URL 和 SSRF**：允许受控 scheme/host，拒绝 loopback/私有网络目标、危险重定向及本地文件协议；克隆时设置资源上限。
2. **仓库隔离**：为第三方不可信仓库使用容器/用户权限隔离；绝不信任其构建脚本与 hook。
3. **凭据与敏感内容**：token 仅存密钥管理器/加密存储，不写日志、不随扫描报告和提示词输出；支持用户审核出站数据预览。
4. **AI 输入**：处理 prompt injection、输出结构校验、引用校验、成本/速率预算；不得听从代码注释中的攻击指令。
5. **团队权限**：Workspace、Repository、Page、Citation、SourceSnippet、Search、Export 均需授权控制，不能因公开 Wiki 就开放私有代码。
6. **Webhook**：验证 GitHub 签名、投递幂等、合法安装来源，防重复任务和越权仓库同步。
7. **文档安全**：Markdown/HTML 消毒，图表和链接过滤，附件内容安全扫描，禁用任意脚本执行。
8. **完整审计**：记录发布者、审阅者、文档版本、模型/模板版本和数据来源，不把原始秘密写入审计日志。
9. **修订防护**：生成器不得静默覆盖人工段落；变更经审核才能发布。
10. **依赖审计**：引入外部源代码或大型运行时前核查 LICENSE/NOTICE、供应链和许可证兼容性。

发现问题请使用私有方式向仓库维护者披露；不要在公开 Issue 里粘贴未脱敏凭据或私有仓库内容。
